<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Split rows -> tokenizer | Local rows become token IDs and labels consumed by training; malformed assistant/solution text can poison labels. |
| Tokenizer raw IDs -> truncated IDs | Truncation can silently remove SOLUTION content unless measured before clipping. |
| Tokenized table -> Arrow files | Serialized files become Phase 4 input artifacts and must not drift into legacy paths/formats. |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-duplicate-split | Tampering | tokenization dispatcher | mitigate | Tokenize only rows from the already gate-passed split plan; retain split overlap gate before Arrow writes. |
| T-03-path-drift | Tampering | `write_arrow_split` | mitigate | Write only `data/tokenized/v3/{train,val,ood_val}.arrow`; do not call Parquet writer or legacy split names. |
| T-03-truncation | Integrity | `tokenize_record` and aggregate stats | mitigate | Compute untruncated raw lengths first, check native IDs on raw IDs, fail closed when truncation_rate > 0.05, and persist stats/truncated IDs. |
| T-03-reproducibility | Repudiation | tokenized row metadata | mitigate | Include record/prompt/assistant hashes, raw_length, truncated flag, split, and lineage in Arrow rows and manifest outputs. |
</threat_model>
