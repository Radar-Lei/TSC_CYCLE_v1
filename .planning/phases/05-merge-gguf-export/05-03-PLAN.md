<objective>
实现 EXP-05 的三精度 parity 测试。**为避免 DGX Spark unified memory 死锁，把单进程改成 4 个独立子进程串行**：
1. parity_hf.py — HF bf16 only（进程退出释放显存）
2. parity_gguf.py --gguf-path bf16 — GGUF bf16 via llama-cli
3. parity_gguf.py --gguf-path q4_K_M — GGUF q4_K_M via llama-cli
4. parity_merge.py — 合并三份 JSON 算 MAE，写 parity_report.json，处理 STATE.md flag

主入口 `parity.py` 用 `subprocess.run` 串行调起这 4 个子进程；阶段之间不共享 python 解释器。前置检查 swap=off。

修复已知 bug：现有 `tsc_cycle/eval/parity.py` 的 `_gguf_generate` 没有 `-ngl`，timeout=180s，CPU-only 推理超时。新脚本必须加 `-ngl 99 --threads 4 timeout=600`，n_predict=384。

Output: `runs/20260507T032419Z/gguf/parity_report.json`（+ 三份中间 JSON）。
</objective>

       ```python
       hf_sol = hf_results[sid]["solution"]
       q4_sol = q4_results[sid]["solution"]
       if hf_sol is None or q4_sol is None: parse_failures.append(...); continue
       common = sorted(set(hf_sol.keys()) & set(q4_sol.keys()))
       diffs = [abs(int(hf_sol[k]) - int(q4_sol[k])) for k in common]
       per_prompt.append({"sample_id": sid, "split": ..., "mae_q4_vs_hf": sum(diffs)/len(diffs),
                          "hf_solution": hf_sol, "bf16_solution": ..., "q4_solution": q4_sol,
                          "hf_tail": ..., "bf16_tail": ..., "q4_tail": ...})
       ```
    3. overall_mae = mean(per_prompt[*].mae_q4_vs_hf)
    4. 写 parity_report.json:
       ```
       {
         "n_prompts": N,
         "n_parse_failures": K,
         "parse_failures": [...],
         "overall_mae_q4_vs_hf": <float>,
         "mae_threshold": 3.0,
         "mae_exceeded": <bool>,
         "per_prompt": [...],
         "timing": {
           "hf_total_sec": <from hf json>,
           "gguf_bf16_total_sec": <from bf16 json>,

         }
       }
       ```

       - run parity_merge
    4. 每段 subprocess.run check=True；任何一段非零退出，主进程同样退出（保留子进程退出码）。
    5. 末尾 print "[PARITY] ALL OK report=<path>"。

    **重要**：parity.py 自己**不**加载任何 torch / transformers / gguf 模型；只做 orchestration + swap 检查 + nvidia-smi 诊断。这是避免 unified memory 死锁的核心。
  </action>
