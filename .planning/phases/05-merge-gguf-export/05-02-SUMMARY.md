# Phase 05 Plan 02: Deterministic Parity Prompts Summary

固化了 20 个 (10 same-dist + 10 OOD) 评测样本到 `runs/20260507T032419Z/gguf/parity_prompts.jsonl`，让 Plan 03 的三精度 (HF / GGUF bf16 / GGUF q4_K_M) parity 测试跑同一组 prompts，确保量化回归可比。

## What Was Built

### `tsc_cycle/student/parity_prompts.py` (136 行)

CLI 工具，参数：
- `--labeled` (default `data/labeled.jsonl`)
- `--out` (default `runs/20260507T032419Z/gguf/parity_prompts.jsonl`)
- `--n-id` / `--n-ood` (default 10 / 10)
- `--seed` (default 42)
- `--include-trivial` flag（默认排除 trivial 样本）

流程：流式扫 labeled.jsonl → 按 `split_hint` 分桶 → 排序后 `random.Random(seed).sample` 抽 id，`random.Random(seed+1).sample` 抽 ood → 顺序合并 (id 先 ood 后) 写出 → stdout 打印汇总。

### `runs/20260507T032419Z/gguf/parity_prompts.jsonl` (20 行, ~600KB)

20 条记录，每行保留 labeled.jsonl 原始全部字段 (`sample_id`, `split_hint`, `trivial`, `ood_dims`, `input`, `result`)。Plan 03 可直接读 `result.solution` 做教师答案 sanity 对照。

> 注意：该文件因 `.gitignore` 中 `runs/` 模式而**不入 git**。重新生成命令：
> `python -m tsc_cycle.student.parity_prompts`（byte-stable，md5 跨次运行一致）

## Schema Notes (实测 vs 计划)

Plan 中假设记录顶层有 `solution` 字段；实测 `head -1 data/labeled.jsonl` 显示：
```
keys: ['sample_id', 'split_hint', 'trivial', 'ood_dims', 'input', 'result']
result.keys: ['success', 'reasoning', 'solution', 'raw', 'usage', 'error', 'attempt_count', 'elapsed_s', 'response_id']
```
教师 SOLUTION 在 `result.solution`。脚本不解析 SOLUTION（透传整记录），所以这个差异对本 plan 无影响；Plan 03 需要从 `record["result"]["solution"]` 取教师答案。

## Deviations from Plan

**None as code deviations.** Two minor mechanical adjustments记录如下：

1. **[Schema 对齐]** Plan 提到"按实际字段写"——实测确认 trivial 字段全 False、teacher solution 在 `result.solution`。脚本透传完整记录而非剪裁，与 plan 第 4 步指示一致。
2. **[Bucket 排序]** 脚本在 `random.sample` 前对桶按 `sample_id` 排序。Plan 未明确要求，但这是 deterministic 抽样的必要前提（否则若 labeled.jsonl 文件 inode 顺序变化，列表顺序就会变）。属 Rule 2（关键正确性补强）。
